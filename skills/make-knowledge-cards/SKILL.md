# Make Knowledge Cards

## Overview

把一篇文章（用户粘贴的文本，或本地 .md / .txt 文件）提炼成 5~8 张原子化知识卡片，用于复习与速记。一张卡片只讲一个知识点，严格忠实于原文。

## Workflow

1. **获取原文**：用户直接粘贴文本就直接使用；给出本地文件路径就完整读取该 `.md` / `.txt` 文件。保留原文结构与措辞，不要改写原文再分析。
2. **通读抓点**：通读全文，列出候选知识点——关键概念、事实、原理、步骤、规则、注意事项、结论。
3. **去重筛选**：合并讲同一件事的卡片，剔除过渡句、寒暄句、纯举例而无独立知识点的内容。
4. **确定数量**：目标 5~8 张。
   - 内容充实的长文：最多 8 张，只保留最重要的知识点。
   - 内容单薄的短文：有几张算几张（可能 2~4 张），**禁止用空洞标题、自创例子或重复内容凑数**。
5. **逐张撰写**：按下方卡片结构写每张卡片。
6. **交付前自检**：按末尾清单逐条核对后再输出。

## 卡片结构（每张卡片四个字段缺一不可）

- **标题**：短，直接命名这个知识点（中文约 15 字以内）。
- **核心知识**：一句话说清这个点是什么。
- **简明解释**：1~3 句白话解释，不堆砌术语。
- **例子 / 自测**：要么用原文中的具体例子，要么出一道自测题，题目答案就是核心知识本身。

## 输出格式

用 Markdown 输出，语言与原文一致（中文文章就输出中文卡片）：

```
# 知识卡片：<文章主题>

## 卡片 1 · <标题>
- **核心知识**：……
- **简明解释**：……
- **例子 / 自测**：……

## 卡片 2 · <标题>
……
```

不要加多余的开场白；除非用户要求，不要额外讲解。

## 忠实性硬规则

- 只写原文里有的信息。**不得引入外部常识、背景知识或"通常来说"的内容**冒充原文观点。
- 不得编造原文没有的数字、人名、书名、引文、例子或自测题答案。
- 原文没讲清楚的点，要么跳过，要么把自测题写成"文中是如何说明……的？"，绝不替原文编答案。
- 一张卡片一个点：两张卡片教的是同一件事就合并。
- 原文实在凑不齐 5 个有效知识点时，少出几张，并一句话说明，例如："原文只包含 3 个有效知识点，未强行凑数。"
- 若原文是纯叙事/抒情、几乎没有可提炼的知识点，如实说明"原文没有足够知识点可做卡片"，不要把叙述句硬包装成知识点。

## 边界（不支持的能力）

- 接受：粘贴的文本、本地 `.md` / `.txt` 文件。
- 不做：网页抓取/爬虫、PDF 与 DOCX 解析、Anki 牌组导出（.apkg）、图形化卡片图片或 GUI 界面。
- 用户提出上述需求时，明确说明本 Skill 不支持，请其粘贴纯文本或提供 .md/.txt 文件后再继续。

## 交付前自检清单

- [ ] 每张卡片只讲一个独立知识点，卡片之间没有近义重复。
- [ ] 每句话都能在原文中找到依据，没有编造内容。
- [ ] 正常文章输出 5~8 张；原文单薄时少于 5 张并已说明。
- [ ] 每张卡片都包含标题、核心知识、简明解释、例子/自测四个字段。
- [ ] 例子和自测题答案均来自原文，不是自创。
