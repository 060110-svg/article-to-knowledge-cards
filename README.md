# make-knowledge-cards

一个可开源的 Agent Skill：把用户粘贴的文章或本地 Markdown/TXT 文件，提炼成 **5~8 张原子化知识卡片**，用于复习与速记。

## 1. 项目解决什么问题

读完一篇文章/笔记后，真正想留下的是几个能马上复习的知识点，而不是一大段摘要。现有做法有三个痛点：

- 普通"总结"往往写成一段压缩复述，知识点被揉在一起，没法单独复习；
- 让大模型自由发挥时，容易**编造原文没有的例子和结论**，或者为了凑满数量硬注水；
- 长文里有重复表述时，总结会把同一件事说好几遍。

本 Skill 用一套固定工作流解决这三个问题：一卡一个知识点、严格忠实原文、信息不足时宁可少出卡片也不凑数。

## 2. 主要功能

- 输入用户直接粘贴的文本，或本地 `.md` / `.txt` 文件，输出 Markdown 知识卡片。
- 每张卡片固定四个字段：**标题 / 核心知识 / 简明解释 / 例子或自测问题**。
- 目标 5~8 张卡片：长文最多取最重要的 8 张；短文有几个出几个，并说明"未强行凑数"。
- 自动合并重复知识点，剔除过渡句和无独立信息量的内容。
- 硬约束：只写原文里有的信息，不引入外部常识、不编造数字/人名/引文/例子。
- 纯叙事抒情、无可提炼知识点的文章，如实说明而非硬造卡片。

**明确不做**（边界）：网页抓取、PDF/DOCX 解析、Anki 牌组导出（.apkg）、图形化卡片图片或 GUI 界面。

## 3. 安装方法

本 Skill 是纯提示词目录，**无运行时依赖、不需要安装脚本**：

1. 把整个 `skills/make-knowledge-cards/` 目录复制到你的 Agent 环境的 skills 目录下（与其它 Skill 同级）。
2. 确认目录结构如下即可被发现：

```
make-knowledge-cards/
├── SKILL.md            # 元数据 + 工作流 + 硬规则
└── agents/
    └── openai.yaml     # display_name / 默认提示词
```

3. 如需校验结构，可用官方校验脚本（需要 Python 与 pyyaml）：

```bash
python quick_validate.py path/to/make-knowledge-cards
```

## 4. 使用方法

在支持 Skill 的 Agent 会话中，直接用自然语言触发即可，例如：

- "把下面这篇文章做成知识卡片：……（粘贴正文）"
- "读取 `note.md`，帮我提炼成知识卡片。"
- "把这篇教程压成可以复习的卡片。"

Agent 会读取 SKILL.md 中的工作流，按"获取原文 → 通读抓点 → 去重筛选 → 定数量 → 逐张撰写 → 自检"执行，最后输出 Markdown 卡片。

## 5. 输入输出示例

### 输入

```
Git rebase 与 merge 的区别

merge 会把两条分支的提交历史原样合并，生成一个新的合并提交，历史图是分叉后再汇合的。
rebase 则会把当前分支的提交重新接到目标分支的最新提交后面，历史是一条直线。
merge 安全但历史图乱；rebase 干净但会改写提交哈希，已推送到共享分支的提交不要随便 rebase。
交互式 rebase（git rebase -i）可以合并多个小提交、重新排序、修改提交信息。
```

### 输出

```
# 知识卡片：Git rebase 与 merge

## 卡片 1 · merge 的历史形态
- **核心知识**：merge 把两条分支历史原样合并，生成一个新的合并提交。
- **简明解释**：合并后提交图是"先分叉、再汇合"的样子，保留完整时间线。
- **例子 / 自测**：为什么 merge 之后历史图会出现一个分叉后的汇合点？

## 卡片 2 · rebase 的历史形态
- **核心知识**：rebase 把当前分支提交"摘下来"，重新接到目标分支最新提交之后。
- **简明解释**：合并后历史是一条直线，没有分叉汇合节点。
- **例子 / 自测**：git rebase 之后，提交图会是什么形状？

## 卡片 3 · rebase 的代价
- **核心知识**：rebase 会改写提交哈希，已推送到共享分支的提交不要随便 rebase。
- **简明解释**：改写哈希会让团队成员基于旧提交的工作产生冲突。
- **例子 / 自测**：分支已经推到公共远程仓库，还能随便 rebase 吗？为什么？

## 卡片 4 · 交互式 rebase
- **核心知识**：git rebase -i 可以在合并前整理提交。
- **简明解释**：支持 squash 合并小提交、重新排序、修改提交信息。
- **例子 / 自测**：想把 3 个小提交合成 1 个，该用什么命令？
```

> 短文或知识点稀少的文章会自动减少卡片数量并说明原因，不会凑数。
